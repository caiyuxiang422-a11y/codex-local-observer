# ADR 0017：刘海中级常驻页与即时页面切换

## 状态

已采用；中级页的单一轮廓和可拖动窗口位置策略由 ADR 0018 进一步修订。

## 背景与事实边界

产品有三个展示状态：

- `compact`：只在刘海左右显示两项自选信息；
- `medium`：长期显示项目、Usage、Token、任务与本机摘要；
- `expanded`：临时打开完整详情与设置。

`compact` 和 `medium` 是用户二选一的常驻页面，`expanded` 不是第三种常驻偏好。

必须明确以下边界：

- 第三方应用不能修改或接管 macOS 的物理摄像头刘海；
- AppKit 可以读取当前屏幕安全区和顶部辅助区域，应用只能让自己的透明窗口贴合这些边界；
- 没有硬件刘海的显示器不能伪造黑色缺口，必须使用普通圆角面板回退；
- 官方未返回 Token、Usage 绝对额度或线程 usage 时，界面必须显示未知，不能把百分比换算成虚构 Token；
- 项目完成度来自用户保存的里程碑，不等于代码行数或模型自动判断。

## 决策

### 1. 中级页是一个环绕刘海的完整页面

中级窗口使用 `560 × 224` AppKit 逻辑点。真实刘海路径由三个相交区域组成：

```text
┌────────左肩────────┐  系统摄像头间隙  ┌────────右肩────────┐
└────────────────────┴──────────────────┴────────────────────┘
│                   中级信息主体                              │
│ 项目 Token │ 今日 Token │ 距里程碑目标                      │
│ 任务状态 + CPU / 内存 / 磁盘 / 网络                         │
└────────────────────────────────────────────────────────────┘
```

左肩显示项目名和当前状态，右肩显示官方 Usage 余量和进度条。主体从系统安全区结束位置开始，
肩部向下多延伸 2pt 与主体重合，因此视觉上是一块连续材料；中央摄像头带内不绘制任何应用
像素。页面不复用小页面左右胶囊，也不在小页面上追加一张卡片。

WebView 使用三个同几何的半透明层提供白色高光；AppKit 使用一个带复合 alpha mask 的
`NSVisualEffectView` 提供真实桌面取样。两者统一采用 8pt 外侧内缩、3pt 顶部内缩、
16pt 肩部圆角和 24pt 主体圆角。原生遮罩在隐藏状态下完成 frame、圆角和 mask 更新，最后
一次性显示，避免复用视图时闪出旧的完整矩形。

无硬件刘海时不显示左右肩部，主体铺满为 24pt 圆角普通面板，并保留点击与键盘入口。

### 2. 中级页的信息范围

中级页显示：

- 当前项目与状态；
- 项目 Token；
- 今日或官方最近日 Token；
- 官方 Usage 余量百分比与进度条；
- 距里程碑目标；
- 运行中、失败、待批准数量；
- CPU、内存、项目所在磁盘和网络摘要。

完整任务列表、失败证据、最近变化、详细系统卡片和设置只在 `expanded` 显示。未知值继续
显示“未返回”“未定义”或“—”，不能显示成 0。

### 3. 切换必须即时完成

常驻状态与展开状态之间只有直接状态跳转：

```text
compact  <-> expanded
medium   <-> expanded
```

实现约束：

- 不创建 `opening`、`closing`、`commit` 等中间状态；
- 不使用 FLIP、`requestAnimationFrame`、`transitionend` 或动画兜底计时器；
- React 立即提交目标页面；
- AppKit 只接收一次最终尺寸，固定 `animate: false`；
- 焦点设置与 AppKit 尺寸同步并行发起，不能串行阻塞可见窗口；
- 隐藏的完整页使用 `display: none`，不能继续参与 blur/filter 合成；
- 页面宿主、胶囊、完整页和中级页的切换相关 CSS `transition`、`animation` 和 delay 固定为 0；
- 桌面硬件刘海路径只使用原生 `NSVisualEffectView` 取样，不再叠加 WebKit 全窗口 backdrop blur；
- 原生指针邻近采样使用 50ms 可见态周期；隐藏时退避到 800ms。

快速来回切换用单调递增的 `transitionSequence` 丢弃过期异步结果。这个名称只表示请求顺序，
不表示存在动画。

### 4. 交互和可访问性

真实硬件刘海上的 `compact` 与 `medium` 保持点击穿透，由 AppKit 全局逻辑点坐标判断鼠标
是否接近；`expanded` 才启用焦点和鼠标控件。无刘海回退使用普通 DOM 按钮。

按 Escape 立即回到用户选择的常驻大小。隐藏完整页仍使用 `aria-hidden` 和 `inert`；常驻
大小使用原生 radio 语义。减少透明度和高对比度时使用更实的材质，但仍保持同一几何。

## 成本与替代方案

- 50ms 指针采样比 80ms 响应更快，但会增加可见常驻窗口的 IPC 次数；如果实测电量成本
  明显，应改为 AppKit 事件驱动监视，而不是重新加入动画延迟。
- 中级常驻会持续采集本机指标并绘制更多像素，资源成本高于小页面。
- 保留旧 `transition` wire 枚举只为兼容历史调用；当前前端不得发送它。

## 验收

至少验证：

1. `npm run test` 与 `npm run build`；
2. `cargo fmt --check`、`cargo test --lib`、`cargo clippy --all-targets -- -D warnings`；
3. 中级页 DOM 正文可见，560×224 内底部任务与机器摘要不被裁切；
4. 中级页顶部左右肩围绕 AppKit 实测摄像头间隙，中央带无应用像素；
5. `compact -> expanded -> compact` 和 `medium -> expanded -> medium` 没有 CSS transition、
   JS 中间状态或原生动画；
6. 无刘海外接屏没有假刘海，长项目名和未知数据使用省略或明确未知状态；
7. 实机检查浅色/深色、Retina、减少透明度和多显示器场景。
