# ADR 0020：统一光谱轮廓与摘要窗口层级

## 状态

已采用。

摘要视图中的 `foreignObject + mask` 方案已被后续 [ADR 0021](0021-webkit-safe-spectrum-and-camera-band-hit-testing.md)
取代；本文的数据层级与窗口层级决策仍然有效。

## 问题

摄像头安全区紧凑视图需要更透明的膜玻璃，但 Usage 轨道的蓝色辉光会在视觉上粘住外圈。
摘要与详细视图只有白色边缘，和紧凑视图的流动光谱语言不一致。摘要视图还需要在不改变
顶部锚点的前提下，允许普通应用窗口覆盖。

## 决策

1. 玻璃仍分为原生背景采样、WebView 光谱边缘和独立内容三层。只降低硬件紧凑视图的乳白
   雾化强度，不改变文字层 opacity，也不增加第二层 CSS blur。
2. 硬件紧凑视图把 Usage 标签和值排在同一行，轨道保留 2px 高度并缩小蓝色辉光，使文字、
   轨道和 2pt 光谱外圈各有真实间距。
3. 摘要与详细视图复用一个仅做 transform 旋转的 conic-gradient 光谱轮。硬件摘要的 mask
   直接使用玻璃本体的 `contour.path`；无硬件/浮动摘要使用 28px 圆角，详细视图使用 30px
   圆角。旧白色 rim 在新边缘启用时退出，避免双边框和转角漏色。
4. 窗口层级由位置、当前视图和 `pinned` 共同解析：

   | 位置与视图 | 置顶 | 允许覆盖 |
   | --- | --- | --- |
   | 摄像头安全区紧凑/详细 | `mainMenu + 3` | 不提供 |
   | 摄像头安全区摘要 | `mainMenu + 3` | `Desktop + 1` |
   | 浮动窗口 | `mainMenu + 3` | `NSNormalWindowLevel` |

   `Desktop + 1` 避免普通窗口层级触发 AppKit 将顶部窗口移到菜单栏下方，但它仍位于系统
   菜单栏之下。因此“允许覆盖”是普通应用可覆盖，不是让应用控制或覆盖系统菜单栏。
5. 打开/收起窗口时暂时隐藏并暂停光谱层，避免窗口改帧和 masked layer 同时合成。减少动态
   效果时边缘保持静态；高对比度使用系统蓝；强制颜色模式隐藏渐变并恢复实线轮廓。

## 成本、未知与回退

- 连续光谱动画会增加合成和电量成本，不能宣称零开销。退役的 SVG mask +
  `foreignObject` 已证实有正确性问题；当前纯 SVG stroke 动画的能耗仍需用 Instruments
  Energy Log 在真机实测。
- 摄像头安全区摘要选择“允许覆盖”后，系统菜单栏可能遮住顶部两翼。这是单一原生窗口与
  macOS 层级规则的限制；若必须分别控制两翼和主体，需要拆成多个原生窗口。
- 若硬件摘要的动画在实机持续触发 Paint，先把该轮廓降级为静态光谱边，而不是引入 WebGL
  或额外 requestAnimationFrame。
- 若渐变不可用、强制颜色开启或系统要求减少动态，内容与边界仍可读，不以动画表达状态。

## 验收

1. 硬件摘要的光谱 mask 与玻璃 fill 使用完全相同的 path；摄像头空区不出现应用像素。
2. 摘要和详细视图的光谱边四角闭合，不改变正文布局或点击区域。
3. 紧凑 Usage 文字、进度条和光谱外圈不重叠。
4. 摄像头安全区摘要可在置顶和允许覆盖之间切换；紧凑与详细视图仍保持顶部锚点。
5. 减少动态、高对比度和强制颜色回退可用；前端和 Rust 策略测试覆盖上述矩阵。
