# ADR 0016：本机编码环境系统指标

## 状态

已采用（macOS/Tauri 第一版）。

## 背景

仅看 Token、任务和 Git 状态，无法解释一次构建为什么变慢。开发者还需要知道
当前机器是否 CPU 饱和、内存有压力、项目所在磁盘快满、网络接口是否在线，以及
笔记本是否在低电量运行。用户要的是可帮助排查编码环境的事实，不是一个会把未知
传感器猜成 0 的“性能分数”。

## 决策

新增一个统一的只读 Tauri 命令 `get_system_metrics`。命令一次返回 CPU、内存、
项目所在磁盘卷、网络和电池五类快照；React 主窗口和浮动便签都只消费
`src/systemMetricsModel.ts` 的规范化模型，不直接处理 macOS API 或命令输出。

原生采集器位于 `src-tauri/src/system_metrics.rs`：

- `sysinfo 0.39.6` 提供 CPU、进程、内存、磁盘和网络接口计数器；采集器实例在
  Tauri 状态中复用，CPU/网络/磁盘速率由相邻采样差值计算。
- macOS 使用 `battery 0.7.8` 读取 IOKit 电池信息。没有电池是合法的“无电池”状态，
  不等于 0%。
- 磁盘按项目路径匹配最长挂载点，容量表示项目所在卷，不宣称是项目目录自身占用。
- 网络优先选择系统默认路由接口；只读本机接口计数器，不自动运行 `ping`、
  `networkQuality` 或外部带宽测试。
- Codex CPU/RSS 仅按进程名包含 `codex` 的本机进程做近似聚合，并在证据中明确
  这可能包含 App Server 或观察台自身；不会读取命令行、Prompt 或登录凭据。

## 数据契约与状态

每个指标都带 `state`、`source`、`updatedAt`、`confidence` 和有界 `evidence`。
缺失值保持 `undefined`；前端规范化器会把 malformed/null 输入降级为“未知/部分数据”。
整体状态只有在五项都可核实时才是 `known`，否则为 `partial` 或 `unknown`。

CPU 的进程百分比按逻辑核心数归一化到 0–100%，同时保留 `codexCpuCores`（逻辑核心
等价数），避免多核进程的原始值被截断。内存压力是 available/total 的本地提示规则，
不是 macOS 活动监视器的官方压力曲线。网络“在线”只说明接口有 IP 且处于可用状态，
不代表 Codex API 一定可达。

## 刷新策略

- 主窗口在用户点击“查看项目”后采集，并以 5 秒间隔轮询。
- 便签只在展开态以 5 秒间隔轮询；收起态不运行五项详细采集。
- 电池 IOKit 读数在采集器内约 30 秒缓存一次，避免展开便签时反复唤醒硬件传感器；
  电池对象的 `updatedAt` 保留实际读取时间。
- 第一帧 CPU、网络和磁盘 I/O 速率可能为空，下一次采样后才显示；不能用 0 代替。
- 电池剩余时间、温度、频率、延迟、Wi‑Fi 信号等硬件/系统字段可选，缺失时显示未知。

## 为什么不用外部命令做主采集

频繁调用 `system_profiler`、`pmset`、`networkQuality` 会更慢、输出格式更易漂移，
还可能触发权限或外部网络副作用。`route -n get default` 只用于识别默认接口，
并不执行网络探测。若以后增加“主动诊断”，应设计成用户明确触发、带超时和单独权限
说明的功能，而不是混入常规快照。

## 验收与边界

- 前端 `systemMetricsModel.test.ts` 覆盖未知值、百分比边界、格式化和显示文案。
- Rust 单元测试覆盖挂载点匹配、数值边界、证据上限和真实快照序列化形状；不对某台
  机器的 CPU、磁盘或电池数值写死断言。
- 该功能与 Codex Token/Usage 分开统计；本机资源不能推导订阅剩余 Token。
- App Store 沙盒、无电池设备、外接卷、VPN/虚拟网卡和多显示器环境都可能使部分
  字段不可用。发布前仍需在目标 macOS 版本上做签名、公证和权限验收。
