# ADR 0018：单一安全区轮廓与可拖动浮动窗口

## 状态

已采用。

## 背景与已核实边界

摘要视图原本用左肩、主体、右肩三个各自带圆角和高光的元素拼接。即使三块重叠，独立边缘仍会
让它们看起来像三张卡片。设置中的“完成”按钮虽然位于 DOM 末尾，但 `position: sticky` 会把它
悬在滚动内容上方。

产品还需要两种互不混淆的窗口概念：

- `placementMode` 决定窗口停靠摄像头安全区，还是成为可拖动浮动窗口；
- `pinned` 决定浮动窗口和摄像头安全区摘要视图是否始终显示在其他窗口上方；
  摄像头安全区紧凑与详细视图仍固定使用系统顶部层级。

第三方应用不能移动、修改或接管 Mac 的物理摄像头外壳。浮动模式只能移动本应用自己的
透明 AppKit 窗口，不能移动系统摄像头外壳。

## 决策

### 1. 摘要视图只使用一个外轮廓

React 用一个 SVG path 描出完整材料：左肩、真实摄像头凹口、右肩和下方主体都在同一个闭合
路径中。整个路径只拥有一份半透明填充、一条 rim 和一组 drop shadow；旧的三个 material
元素不再渲染。

AppKit 的 `NSVisualEffectView` 同样使用单个 `NSBezierPath` alpha mask，不再填充三个独立
圆角矩形。真实摄像头间隙在安全区高度内保持透明；无摄像头外壳或浮动模式使用完整圆角矩形，不能
伪造黑色缺口。

### 2. 新增独立窗口位置偏好

`WidgetPreferences` 持久化：

```text
placementMode = notch | floating
pinned        = true | false
restingMode   = compact | medium
floatingMediumMetrics = [left, center, right]
```

旧偏好没有 `placementMode` 时回退为 `notch`。非法值也回退为 `notch`。

`notch` 模式继续由 AppKit 贴合当前显示器的安全区和真实摄像头中心。`floating` 模式：

- 使用同一 React 数据树和详细、摘要、紧凑视图，不复制指标逻辑；
- 关闭摄像头安全区 proximity IPC 轮询；紧凑和摘要视图只通过独立的“展开详细视图”按钮展开，指标表面本身不是点击目标；
- 展开后移除紧凑视图的展开按钮，顶部两项指标恢复左右双栏，并只保留工具栏中的一个收起按钮；详细视图持续到用户点击该按钮、按 Escape 或隐藏窗口；键盘可用 Enter/Space 激活展开按钮；
- 展开前读取并暂存默认视图的 AppKit 逻辑点 frame；详细视图仍围绕该锚点无动画展开并限制在当前屏幕 `visibleFrame`，收起时再次使用原锚点，因此屏幕边缘的 clamp 不会累积成位置漂移；
- 开启窗口鼠标交互和 movable 属性；
- 浮动窗口以非交互玻璃和标题空白作为直接拖动表面，调用 Tauri 原生 `startDragging()`；按钮、表单、设置、可滚动正文与可选择文字区域必须排除，避免拖动手势抢占正常操作；
- 页面尺寸切换固定 `animate: false`，不加入 CSS 尺寸或 transform 过渡。浮动紧凑视图的整体表面和展开按钮也不使用按压缩放，
  只用颜色变化表示按下，避免用户误认为窗口先缩小再打开。
- 浮动和摄像头安全区紧凑视图共用 AppKit 原生磨砂材质、克制的透明雾化色和 2pt 光谱边缘，不挂载 WebGL 光学层。
  摄像头模式的左右材质互相独立，中央间隙保持透明；光谱仅旋转静态渐变的合成层，“减少动态效果”下保留静态边缘。

默认视图锚点只在一次展开/收起周期内保存在前端内存；即使用户拖动详细视图，收起仍回到展开前的默认视图位置。
当前版本只保证运行期间保留浮动位置；没有承诺重启后恢复坐标。若后续持久化坐标，必须同时
处理多显示器拔插、分辨率变化和不可见坐标恢复，不能只保存裸 `x/y`。

### 3. 设置完成按钮回到文档流

按钮保留为设置内容最后一个元素，并改为 `position: static`。设置面板只有一个滚动容器，用户
滚到真正底部才看到“完成”；不再用第二个 sticky 操作层覆盖表单。

### 4. 窗口层级使用显式双选控制

`pinned` 继续作为唯一持久化字段，不新增第二套窗口层级状态。设置界面把旧复选框改为
“保持在最前方 / 标准窗口层级”双选控件；保存时仍通过同一个原生窗口层级命令应用。
该控件在 `floating` 模式和摄像头安全区 `medium` 模式可编辑。摄像头安全区紧凑与详细
视图固定使用 `mainMenu + 3`；摘要视图取消置顶时使用 `Desktop + 1`，因此不触发
`NSNormalWindowLevel` 把窗口下移到菜单栏下方的约束。完整策略与风险由 ADR 0020 补充。

## 成本与风险

- 浮动模式会接收鼠标事件；这与摄像头安全区紧凑视图的点击穿透不同，但属于可拖动窗口的必要成本。
- 浮动窗口启用键盘焦点后，点击控件可能切换当前键窗口；默认视图不会因鼠标经过而展开。
- 拖动位置尚未跨重启持久化。直接持久化绝对坐标会在显示器拓扑变化后产生离屏窗口，因此本次
  不做未经恢复策略验证的“半持久化”。
- AppKit 与 SVG 路径分别由原生坐标和前端模型生成；实机需要继续验证非对称辅助区域、多显示器
  和不同 safe-area 高度。数据未知状态、Token 来源和项目完成度规则不受位置模式影响。
- 摄像头安全区摘要视图使用 `Desktop + 1` 时可以被普通应用覆盖并保持顶部坐标，但系统
  菜单栏本身仍可能覆盖顶部两翼；若要同时保证两翼永远清晰和主体可覆盖，需要拆分原生窗口。
- 默认视图锚点没有跨重启持久化；这是为了避免显示器拔插后恢复到屏幕外。详细视图中的拖动也不会
  静默改写默认视图锚点，用户需要收起后再拖动默认视图来更新其位置。
- 常驻光谱边缘会让浮动紧凑视图保持一个、摄像头安全区紧凑视图保持两个小型合成动画层，加上原生模糊后电量开销不会为零。WebGL 仍在这些状态关闭，
  但还需使用 Instruments Energy Log 建立实机基线，不宣称零功耗。

## 验收

1. 前端偏好迁移、轮廓模型、构建测试通过；
2. Rust placement、frame clamp、单一遮罩与兼容路径测试通过；
3. 摄像头安全区摘要视图没有肩部/主体接缝，中央摄像头区域不绘制应用像素；
4. 浮动模式的非交互表面可直接拖动且不显示专用拖动按钮；详细、摘要、紧凑视图与安全区模式显示同一批数据，所有按钮、表单、滚动和文字选择仍正常工作；
5. 浮动模式展开时以默认视图 frame 为锚点并处于 `visibleFrame` 内；收起后精确返回原位置，且没有中间动画；
6. 切回摄像头安全区模式后重新锚定系统安全区；
7. “完成”只在设置滚动内容的真实底部出现。
8. 浮动紧凑/摘要视图只响应独立的展开按钮；点击指标表面、鼠标经过或移出都不会改变视图；明确收起和 Escape 均可返回。
9. 浮动详细视图顶部两项指标保持左右双栏，DOM 中只存在一个“收起浮动窗口”按钮；浮动摘要视图的 28pt 圆角不会出现越界阴影尖角。
10. 摄像头安全区摘要视图没有外部暗色 drop-shadow；其窗口层级双选控件与浮动模式共用
    `pinned` 单一状态，紧凑与详细视图不受该选择影响。
11. 浮动与摄像头安全区紧凑视图都是原生磨砂底与 2pt 动态光谱边，光谱内外边与各自宿主使用同心圆角，不创建 WebGL context；
    摄像头中央间隙不存在材质子节点。浮动紧凑视图的 Usage 进度条与光谱边之间有独立间距，并不与文字重叠。
12. 浮动摘要视图的中间三栏可分别选择指标；旧偏好自动恢复为“项目 Token / 今日 Token / 项目进度”，非法或缺失槽位逐项回退且未知数据不显示为 0。
