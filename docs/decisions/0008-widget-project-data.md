# ADR 0008：快览便签的项目与账户数据接入

## 状态

已采用（2026-08-30）。

## 问题

便签虽然收到了正确项目路径，但只读取 `widget-task-history-v1.json` 和
`project-progress-v1.json`。当前机器上这两个文件都不存在，因此 Token、任务历史、
完成度和变化只能是空或未知；主窗口已经接通的官方项目/账户适配器没有被便签复用。
同时，便签缩到最小高度时，CSS Grid 会压缩卡片本身，导致已有的 `0`、`—`、说明和
证据也只剩标题可见。

## 已核实事实

- 工作区注册表中的活动路径与用户选择一致，路径传递和 camelCase 序列化没有失败。
- 2026-08-30 的公开 App Server 探针为当前目录匹配到 19 个线程，但 19 个
  `threadUsage` 都是 `null`；项目历史 Token 不能据此写成 0。
- 同一官方账户快照能返回计划类型、账户 Token 活动和 rate-limit 窗口百分比。
- 运行/失败任务仍只能覆盖本观察台启动的 `codex exec --json` 任务；当前公开链路不会
  自动发现其他 Codex 桌面任务。

## 决策

1. 便签继续使用本地 `get_widget_snapshot` 获取任务、里程碑和变化；并行复用已经归一化的
   `get_project_usage` 与 `get_account_usage` 适配器。渲染层不解析原始 JSON-RPC。
2. 官方项目 Token 与本工具任务 Token 采用“优先/回退”，永不相加，避免覆盖范围重叠时
   重复统计。官方返回 `null` 时显示会话数、来源和原因。
3. 账户最近日 Token、账户累计活动、计划类型和窗口剩余百分比可在便签显示；百分比不换算
   成绝对 Token。便宜的本地快照按用户设置的 2–60 秒更新，官方快照每 5 分钟更新或由用户
   手动刷新，降低常驻窗口的 CPU、网络和电量成本。
4. 主窗口选择项目时只更新便签的原生项目状态并发送 `widget-project-changed`，不会强制打开
   或抢占焦点。前端用请求序号丢弃晚到的旧项目结果。
5. 数据区改为不可压缩卡片组成的 Flex 列；内容区滚动。设置改成独立玻璃浮层，不再把数据区
   高度压成 0。后台失败且无快照时显示明确重试入口。

## 风险与未知项

- App Server 仍可能超时、断线或改变字段；便签应保留上一个账户值并显示部分读取错误。
- 当前项目的官方历史 Token 在本账号上仍不可得。该限制不能通过 UI 修复，也不应读取
  `auth.json`、Cookie、私有存储或抓取官方桌面界面绕过。
- 官方账户累计 Token 是活动量，不是订阅额度；窗口百分比也没有公开的固定 Token 分母。
- 长期需要跨窗口共享缓存、完整历史和迁移时，应按项目标准迁移到 SQLite，而不是继续扩大
  前端状态和小型 JSON 文件。

## 回退方案

若官方低频轮询造成兼容性或资源问题，可关闭自动轮询，仅保留顶部手动刷新；本地任务和
里程碑快照仍可独立工作。若无边框小窗在某平台无法稳定布局，可恢复系统标题栏，不改变数据
适配器。
