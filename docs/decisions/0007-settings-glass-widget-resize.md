# ADR 0007：设置入口、玻璃材质与可缩放便签

## 状态

部分被 [ADR 0009](./0009-top-edge-notch-shelf.md) 取代（2026-08-30）。主窗口设置入口、数据区可滚动和无障碍回退仍有效；便签自由拖动、用户缩放、300×72 收起态和可用工作区定位已废弃。

## 问题

高级能力和工作区管理属于低频诊断操作，直接堆在首屏会掩盖单项目驾驶舱的核心信息。与此同时，便签窗口是无系统边框的可缩放窗口：旧布局在条件面板出现或窗口变矮时可能把数据区域挤出视口，且仅依赖声明式拖动区域在部分 WebView/平台组合中不稳定。

## 已核实事实

- Tauri 的 `widget` 窗口配置为无 decorations、可缩放，前端可以调用 `startDragging` 发起原生窗口拖动。
- `core:window:default` 权限集合不包含 `start-dragging`；调用该 API 需要显式加入 `core:window:allow-start-dragging`。
- 便签内容的错误提示、设置面板和数据列表是条件渲染的，子节点数量不是固定值；用固定数量的 CSS Grid 行无法保证数据区始终拿到 `1fr`。
- 玻璃效果依赖 WebView 的 `backdrop-filter` 支持；过度透明会降低中文和大数字的对比度，因此必须保留实体背景和 reduced-transparency 回退。

## 决策

1. 在主窗口顶栏提供单一“设置”入口。高级能力探测、刷新和工作区登记/切换/移除集中在玻璃弹出层；主监控区只保留“查看完整监控”折叠入口。
2. 采用平台原生字体、克制的蓝色语义强调、半透明表面、模糊/饱和度和细内高光，形成 Apple-inspired 的膜玻璃层次。材质不是数据来源；所有状态仍显示来源和未知边界。`prefers-reduced-transparency`、`prefers-reduced-motion`、暗色和高对比模式提供回退。
3. 将便签外壳改为 Flex 列布局：标题栏、范围/错误/设置区固定占用自身高度，数据区使用 `flex: 1 1 0; min-height: 0; overflow: auto`。这样缩小窗口时数据保留在可滚动区域，而不是被裁剪。
4. 标题栏保留 `data-tauri-drag-region`，并在非按钮/输入控件的左键按下时显式调用 `getCurrentWindow().startDragging()`。权限文件只增加该单项窗口权限，不扩大文件、网络或命令权限。
5. 主窗口打开便签时把当前项目路径交给 Rust 窗口状态；便签初始化和刷新优先使用该路径，避免因为工作区旧选择而显示别的项目。
6. 便签采用两态窗口契约：收起态约 300×72，只保留胶囊、项目 Token 和主窗口余量；鼠标进入、靠近胶囊约 48 个物理像素或键盘聚焦后展开到约 380×520，数据区继续使用可滚动 Flex 布局。窗口首次创建时按当前显示器可用工作区顶部居中，后续显示保留用户拖动位置。动态尺寸/位置与邻近检测调用所需的 `outer-position`、`outer-size`、`cursor-position`、`set-position`、`set-size` 权限在 capability 文件中显式声明。

## 风险与边界

- 玻璃材质在不支持 `backdrop-filter` 的环境会退化为实体色，不应影响数据正确性。
- 原生拖动事件无法在当前自动化环境中模拟完整的鼠标手势；已通过 Tauri 构建、权限嵌入检查和类型/单元测试验证，最终仍需在目标桌面上手动拖动确认。
- 便签仍只统计本工具启动且已保存的任务；它不会因此获得其他 Codex 客户端的任务或账户绝对 Token 配额。
- “灵动岛式”胶囊不是 macOS 系统组件。邻近检测只在便签显示期间低频读取本机光标位置；当前 macOS 原生桥接读取公开的 AppKit 屏幕安全区来定位窗口，但不调用私有 CGS/SkyLight API，也不能占用或修改硬件刘海。若运行时拒绝光标位置权限，会自动退回窗口悬停与键盘聚焦触发。

## 回退方案

若玻璃效果导致可读性或性能问题，可只保留半透明表面和边框，关闭 `backdrop-filter`；若原生拖动在某平台仍不支持，可恢复系统 decorations 或增加平台专用拖动区域，不改变数据适配器。
