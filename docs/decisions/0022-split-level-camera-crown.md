# ADR 0022：摘要正文与顶部状态翼分层

## 背景

摄像头安全区摘要视图需要同时满足两个互相冲突的窗口行为：下方摘要正文可以被普通应用
覆盖，而摄像头左右的基础状态仍保持可见。`NSWindow.level` 是整窗属性；CSS `z-index`、
同窗 `NSView` 和 `NSVisualEffectView` 都不能让一个窗口中的不同区域进入不同的
WindowServer 层级。因此，继续调整单窗样式无法实现该需求。

## 决策

1. 保留主 `widget` 窗口承载完整摘要视图；当用户选择“仅正文允许覆盖”时，主窗口使用
   `DesktopIcon + 1`。这一级别位于 Finder 桌面文件之上、普通应用窗口之下；不能使用
   `Desktop + 1`，因为后者仍在桌面文件层下面。
2. 新增隐藏启动的 `widget-crown` 透明伴随窗口。它覆盖屏幕顶部会遮挡低层窗口的完整菜单栏
   保留带，宽度和横向位置跟随主摘要窗口。它不另外设计两枚胶囊，而是渲染完整摘要轮廓后，
   只裁取原界面的顶部一带；因此左右状态翼、玻璃和光谱边缘仍是上一版的一体化 UI，
   中央摄像头区域保持透明。主窗口会同时裁掉这段重复的顶部材质，避免双层叠加产生色差。
3. 伴随窗口固定使用 `NSMainMenuWindowLevel + 3`，不可聚焦、点击穿透、无阴影，并加入
   所有 Space。它只在以下条件全部成立时显示：

   - 位置为摄像头安全区；
   - 当前为摘要视图；
   - 用户关闭整页置顶；
   - 当前屏幕确实存在 AppKit 可测量的硬件缺口；
   - 主窗口可见。

4. 紧凑、详细、浮动、无硬件缺口、整页置顶或主窗口隐藏时，伴随窗口必须隐藏。
5. 伴随页不启动第二套项目、Usage 或系统指标采集。主 `widget` 把已格式化的轻量
   ViewModel 通过 Tauri 窗口事件推送给伴随页；伴随页只负责渲染。
6. 两个窗口的 AppKit 配置必须串行执行，且不能在一个 `with_webview` 主线程回调里同步
   等待另一个窗口，避免主线程死锁。
7. 顶部像素的所有权采用分阶段确认，而不是根据期望状态猜测：第一次同步保持完整主摘要
   位于摄像头安全层，同时安装并置前伴随裁片；伴随 WebView 用稳定的 `sessionId` 对当前
   `presentationId` 发出跨越绘制机会后的确认；第二次原生同步确认伴随窗口仍可见并成功
   安装正文遮罩，才降低主窗口层级并返回 `crownCompanionVisible=true`。主 WebView 最后
   移除重复的顶部材质与内容。旧会话或旧代次的确认不能接管新视图。
8. 伴随窗口是可选增强。窗口创建、遮罩、材质或隐藏失败都不能让主窗口的同步失败；此时
   立即隐藏伴随窗口并恢复主摘要的完整轮廓。隐藏后的主窗口重新显示时会收到专用生命周期
   事件，生成新的视图代次并立即重做同步，不依赖最长 5 秒的几何轮询。周期几何刷新也会
   在调用原生同步前后检查视图代次；同一代次内的交接、重试和周期刷新还使用独立且递增的
   原生操作编号，旧响应不能覆盖较新的窗口状态。后端重新显示保留窗口时，只在真正置前的
   那次调用中按现有窗口高度恢复紧凑、摘要或详细材质；其余旧式生命周期同步不再用
   `interactive=false` 把摘要材质误改成紧凑材质。

## 几何与交互

- 伴随窗口使用主窗口实际所属的 `NSScreen`，不假设主显示器，也允许负坐标显示器。
- 高度取 `max(notchHeight, menuBarHeight) + 0.5pt`，并限制在主摘要和屏幕高度内。原因是
  `DesktopIcon + 1` 的主体会被 WindowServer 遮挡到完整菜单栏底边；在当前实机上菜单栏为
  37pt、摄像头安全区为 32pt，若仍只裁 32pt，二者之间必然出现 5pt 黑带。额外 0.5pt
  只用于 Retina 合成重叠，不改变紧凑视图严格限制在安全区内的指针命中高度。
- 伴随窗口完全点击穿透；展开仍由主窗口的 AppKit 全局指针采样决定。
- 伴随窗口的 CSS 材质、SVG 轮廓和 AppKit 遮罩都使用主摘要的完整几何，再由
  窗口高度裁取顶部；不允许为左右翼引入独立圆角底边。
- 伴随裁片越过菜单栏底边保留 `0.5 pt` 合成重叠；主窗口仍从未裁切的完整轮廓计算阴影后
  再裁取正文，避免 Retina 抗锯齿和裁片投影在交界处形成发暗分界线。
- 主窗口与伴随窗口的摄像头轮廓转折都使用 AppKit 返回的真实安全区高度；只有伴随窗口的
  原生裁切画布延长到菜单栏底边。摘要几何不套用紧凑视图的文字可读性高度下限。
- 收起态展开命中宽度取完整 `closedWidth`，覆盖左右信息翼和中间硬件区；命中高度仍严格
  限制在真实摄像头安全区内，入口外扩为 `0 pt`。

## 限制

- “顶部状态保持在前方”只针对普通应用窗口。锁屏、系统安全界面、菜单栏自有内容以及
  某些全屏系统层仍可能位于应用之上，界面和文档不得承诺“永远不可覆盖”。
- 第二个 WKWebView 会增加少量常驻内存。为避免重复进程和 I/O，它只接收展示数据，不
  运行采集适配器。
- 外接无缺口显示器不会显示伴随窗口，而是继续使用单一兼容布局。

## 验收

1. 纯函数测试覆盖所有显示/隐藏组合。
2. 负坐标显示器测试验证伴随窗口与主摘要同 `x`，贴合屏幕顶边，且不超过安全区高度。
3. 前端测试验证异常事件不会绘制陈旧内容，Usage 百分比会被限制在 `0–100`。
4. 前端测试验证绘制确认携带当前 `presentationId`；原生同步结果明确返回伴随窗口是否已
   安装并置前，失败路径保持完整主摘要。
5. 实机验收需要用普通应用覆盖摘要正文，确认左右状态仍可见、中央区域不拦截菜单栏，
   并检查切换视图、切换显示器、Space 和全屏时不存在孤立伴随窗口。
