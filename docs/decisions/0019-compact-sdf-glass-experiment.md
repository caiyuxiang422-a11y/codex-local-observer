# ADR 0019：紧凑视图 SDF 光学覆层实验

## 状态

已由 ADR 0021 取代。现行实现让浮动与摄像头安全区紧凑视图共享 AppKit 原生材质、
单一 WebGL SDF 光学层及 `CompactGlassChrome`；本文件以下内容仅保留实验过程记录。

## 问题和目标

原紧凑视图主要依靠半透明白色渐变、白边和阴影表达玻璃，轮廓清楚，但容易读成塑料。
本次目标不是一次替换所有页面，而是在始终可见、面积最小的紧凑视图验证以下渲染分工：

1. AppKit 原生材质取样窗口背后的桌面；
2. WebGL2 用解析 SDF 计算玻璃轮廓、厚度场、三维法线、双界面光学响应、三区高光和阴影；
3. React DOM 独立绘制文字、状态、进度条和按钮。

摘要视图、详细视图、数据读取、Token 来源和项目完成度规则不在本实验范围内。

## 已核实事实

- `NSVisualEffectView` 已通过 `BehindWindow` 放在 WKWebView 下方；摄像头安全区紧凑态使用左右两个
  原生材质面，浮动紧凑、摘要和详细视图使用一个与当前窗口轮廓一致的原生材质面。
- WebGL canvas 不能读取位于 WKWebView 下方的 `NSVisualEffectView` 或 macOS 桌面像素。
  若把桌面作为 shader 纹理，需要屏幕捕获和“屏幕录制”权限，这会扩大隐私和维护成本。
- `liquid-glass-react@1.1.1` 的所谓 shader 模式在主线程用 2D Canvas 生成位移图，再交给 SVG
  `feDisplacementMap`；它没有三维高度场、双界面折射或中心/内缘/外缘三区模型，且上游明确提示
  Safari 的 displacement 不可用。它因此保留给既有浏览器预览，不进入本次桌面紧凑视图。
- 物理摄像头区域属于 macOS；第三方窗口只能读取安全区几何并绕开，不能绘制或控制硬件外壳。

## 假设和未知项

- 双界面 `refract` 当前只改变程序化高光与色散方向，**不是**对真实桌面纹理做完整光线追踪。
- 当前本机 WKWebView 探针已验证 WebGL2 上下文、shader 编译和首帧 `ready`；不同
  macOS/WebKit/GPU 组合仍需实机验证。
- 当前只能根据“单画布、DPR 上限 2、事件触发单帧、无循环 RAF”推断开销较低；尚未形成
  GPU 时间和电量基线，不能宣称零开销或零卡顿。

## 可选方案

1. **继续只用 CSS/AppKit。** 最稳定、成本最低，但无法按高度场和法线区分光学区域。
2. **AppKit + WebGL2 程序化光学覆层（采用）。** 不增加权限，能验证 SDF/法线/色散；真实背景
   折射仍由系统材质承担。
3. **屏幕捕获纹理 + 完整双界面折射。** 光路更完整，但需要敏感权限、持续纹理复制和更多功耗，
   与本地常驻信息工具的最小权限原则不相称，本次拒绝。
4. **直接复用 `liquid-glass-react`。** WebKit 位移不稳定且主线程逐像素生成，不适合始终显示的紧凑页。

## 决策

- 浮动紧凑态在单个原生磨砂层上合成一个光谱环；摄像头安全区紧凑态则在左右两个原生材质上各合成一个，
  中央系统摄像头间隙不挂载材质。两种模式共用同一 React 材质结构、雾化色和 2pt 环形遮罩。
- 只旋转光谱环遮罩内的静态渐变轮，不动态重算渐变，不增加 JavaScript RAF。外边、内边与各自原生材质使用同心圆角。
- 摄像头安全区紧凑态的 AppKit 底面与 WebView 指标严格共用 4pt 外边距、8pt 摄像头净空和 3pt 垂直边距；
  圆角随可用高度收缩。光谱 frame 向外预绘 1 CSS px，再由指标父层做唯一一次外轮廓裁切，避免 Retina 抗锯齿叠乘产生白线。
- 摄像头侧白膜只增强静态雾化色和高光，不新增第二层 CSS `backdrop-filter`；真实桌面取样仍只由
  `NSVisualEffectView(Popover, BehindWindow, Active)` 承担，避免双重模糊和塑料感。
- 没有硬件摄像头区域的紧凑回退继续挂载一个透明 WebGL2 canvas，并生成单个 SDF；摘要、详细、浮动紧凑和硬件摄像头紧凑视图不挂载 canvas。
- 高度场由 SDF 内部深度生成，数值差分得到三维法线；空气→玻璃→空气两次 `refract` 只驱动
  光学响应。中心、内缘、外缘分别控制轻微底色、厚度高光和 Fresnel/色散。
- 单片元合成遵循底色、再高光、最后阴影；输出预乘 Alpha，不绘制实心白边。
- AppKit 已确认硬件摄像头时必须继续创建左右两个 `NSVisualEffectView`；只有硬件状态
  仍未知时才延迟原生材质，防止短暂盖住中央缺口。
- AppKit 路径的 shader tint 增加克制的乳白/深灰雾化，并使用约 2 CSS px 对齐的静态微颗粒表达
  表面粗糙度。颗粒不使用时间 uniform，不增加持续 RAF；真实背景模糊仍由 AppKit 负责。
- DPR 上限为 2。只在挂载、ResizeObserver、窗口尺寸/显示器缩放、明暗外观、页面重新可见和
  context 恢复时合并绘制一帧；不建立持续动画，不跟踪鼠标。
- canvas `pointer-events: none`，DOM 内容固定在更高层。只有 shader 成功绘制第一帧后才移除旧 CSS
  填色/白边；WebGL2 缺失、编译失败、context lost、减少透明度、高对比度或强制颜色时恢复旧材质。

## 成本、风险和回退

- 新增约一套 WebGL program 和紧凑尺寸 backing store；需要维护 GLSL 与 AppKit/CSS 几何契约。
- 摄像头安全区会常驻两个小型光谱合成层，比浮动紧凑视图多一个；面积很小，但仍需在实际 WKWebView 上用 Instruments/Paint Flashing 验证功耗，
  不宣称零开销。Browser 预览只能验证 DOM 层级、遮罩和无障碍回退。
- 回退不依赖设置迁移：卸载 `CompactSdfGlass` 即恢复原 CSS/AppKit；运行时失败则通过
  `data-compact-glass-state="fallback"` 自动恢复，不影响项目数据与操作。
- 本实现独立编写，没有复制 `liquid-glass-react` 源码；现有第三方依赖和许可声明保持不变。

## 验收

1. 浮动紧凑视图只有一个光谱材质实例；摄像头安全区紧凑视图有且只有左右两个；
2. 中央摄像头间隙中没有光谱、雾化层、canvas 或其他应用像素；
3. canvas 不接收指针，浮动窗口的展开按钮、拖动和摄像头安全区 click-through 不受影响；
4. SDF 静止时没有持续 RAF；DPR 不超过 2；WebGL context 数量不超过 1；光谱材质只动画渐变轮的 `transform`，
   减少动态效果时停止旋转；
5. WebGL2 或 shader 失败以及辅助功能偏好下，旧材质和全部文字立即可用；
6. 浅色/深色、Retina/外接屏、不同壁纸下无黑边，文字和进度条对比度不下降；
7. 标准 417×32pt 宿主中，左右原生底面与 DOM 指标均为 104×26pt；摄像头两侧各 8pt 净空保持完全透明；
8. 前端测试、构建、Rust 回归检查和 `.app` 打包通过，并如实记录未完成的实机视觉验证。
